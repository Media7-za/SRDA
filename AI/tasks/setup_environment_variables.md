# 1. Task Metadata

Setup Production Environment Variables

## Status
- Not Started

---

# 2. Objective

Securely gather, generate, and inject the necessary environment variables (Secrets, Keys, API URLs) into the production hosting environments (e.g., Vercel, Railway, Render).

---

# 3. Business Context

Leaks of environment variables (like Stripe Secret Keys or JWT secrets) compromise the entire business. They must be managed centrally and securely before ANY code is deployed to production.

---

# 4. Required Context Files

- `/ai/context.md`
- `/ai/agents/devops_agent.md`
- `.env.example` (Source of truth for required variables).

---

# 5. Dependencies

- `setup_production_database.md` (Provides the DB URLs).

---

# 6. Scope

## In Scope
- Generate a cryptographically secure `JWT_SECRET`.
- Retrieve Firebase Admin / Push Notification credentials or URLs.
- Map the Stripe Live Keys (or strict Test Keys if deploying a beta).
- Define `FRONTEND_URL` and `BACKEND_URL` for CORS and redirect logic.
- Inject these securely into the hosting provider's dashboard (e.g., Vercel Project Settings -> Environment Variables).

## Out of Scope
- Actually writing application code.

---

# 7. Inputs
- Secrets generated by password managers or cloud providers.

---

# 8. Required Outputs
- Fully populated environment on the CI/CD or Hosting platform.

---

# 9. Acceptance Criteria
- Every key defined in `.env.example` has a corresponding production value mapped securely in the hosting dashboard.
- CORS values match the registered deployment domains.

---

# 10. Implementation Rules
- If deploying to a Monorepo platform (like Vercel), ensure variables are scoped properly to the relevant apps (e.g., DB strings only go to the Backend/Next.js server environments, never exposed to `NEXT_PUBLIC_` unless specifically required like the Stripe Publishable Key).

---

# 11. API / Data Contracts
N/A

---

# 12. Edge Cases
- Changing a secret later requires triggering a new build/deployment on most platforms.

---

# 13. Testing Requirements
- The Zod configuration built in `setup_environment_config.md` should catch any typos during the deployment startup phase.

---

# 14. Observability / Logging
- None. DO NOT log secrets to the console during setup.

---

# 15. Security / Permissions
- Never paste production `.env` files dynamically into chat logs. Inform the user to paste them directly into the Vercel/Railway dashboard.

---

# 16. Performance Requirements
- Standard.

---

# 17. Deliverable Format
Confirmation of configuration in the cloud platform.

---

# 18. Completion Checklist
- [ ] JWT secret generated securely

- [ ] Stripe webhooks configured
- [ ] CORS domains matched

# 19. Agent Instruction
You are the DevOps Agent. Treat infrastructure as code where possible, but treat secrets with maximum paranoia. Double-check all public prefixes (e.g., `NEXT_PUBLIC_`) to ensure you are not accidentally shipping a Stripe Secret Key to the browser bundle.
